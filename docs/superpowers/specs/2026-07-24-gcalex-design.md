# gcalex 설계 문서

- 날짜: 2026-07-24
- 상태: 승인 대기 (사용자 리뷰 전)

## 1. 목적

구글 캘린더 일정을 가져와 오늘/내일 일정을 매일 알려주고, 캘린더 화면에서 날짜를 탭해
자연어로 일정을 생성·수정·삭제할 수 있는 개인용 iOS 앱.

예시 입력: "월요일(7/1), 수요일(7/3), 금요일(7/5) 오후 1시부터 3시까지 미팅"
→ 세 날짜에 각각 미팅 일정을 구글 캘린더에 생성.

## 2. 범위 및 전제

- **사용자**: 개인용, 단일 사용자(본인)만 사용. 멀티유저/인증 체계 불필요.
- **대상 기기**: iPhone 15 Pro 이상 (Apple Intelligence 호환, A17 Pro+), iOS 26 이상.
- **플랫폼**: 네이티브 iOS 앱 (SwiftUI). 챗봇(카카오톡/슬랙/텔레그램)이 아니라 앱 자체에
  캘린더 UI + 채팅 입력이 통합된 형태.
- **서버**: 없음. 앱이 구글 캘린더 API와 온디바이스 AI 모델을 직접 호출.

## 3. 아키텍처

```
gcalex (iOS 26+ App, SwiftUI, 서버 없음)
│
├─ GoogleCalendarService
│   ├─ GoogleSignIn SDK → OAuth 토큰 발급/갱신 (PKCE, 클라이언트 시크릿 불필요)
│   └─ URLSession → Calendar API v3 (list/insert/patch/delete events)
│
├─ FoundationModelService  (Apple Foundation Models, 완전 온디바이스)
│   ├─ LanguageModelSession (instructions: 오늘 날짜, 타임존, 톤)
│   ├─ @Generable 구조체: EventDraft(title, date, startTime, endTime, ...)
│   └─ Tool 프로토콜 구현체: ListEventsTool / CreateEventTool /
│       UpdateEventTool / DeleteEventTool
│         → 내부적으로 GoogleCalendarService 호출
│
├─ ChatEngine (에이전트 루프)
│   사용자 입력 → LanguageModelSession.respond() 호출
│   → 모델이 필요한 Tool을 스스로 연쇄 호출(예: List→Update)
│   → 최종 자연어 응답 생성 → 파괴적 액션(수정/삭제)은
│     실행 전 확인 카드로 사용자 승인 요구
│
├─ NotificationScheduler
│   BGTaskScheduler로 주기적 백그라운드 동기화 →
│   매일 고정 시각 로컬 알림(UNUserNotificationCenter) 재예약
│
└─ Keychain
    Google OAuth 토큰만 저장 (AI API 키 없음 — 온디바이스라 불필요)
```

외부 네트워크 통신은 Google Calendar API 호출뿐. AI 파싱/추론은 전부 기기 내부에서
처리되며 API 키·비용·네트워크 의존성이 없다.

### 채택 이유

- **UICalendarView** (네이티브 iOS 16+ 달력 컴포넌트): Apple 캘린더와 동일한 룩앤필을
  최소한의 커스텀 UI 코드로 확보. 대신 이벤트 도트 데코레이션 커스터마이징은 다소 제한적.
- **Foundation Models + Tool 프로토콜**: Claude API 같은 클라우드 tool-use 패턴을
  온디바이스에서 동일하게 구현 가능(iOS 26, WWDC 2025/2026). 무료·오프라인·프라이빗이며
  Korean(한국어)도 지원 언어에 포함(베타). 모델 크기(3B)로 인해 매우 복잡한 다중 모호
  참조 추론은 클라우드 대형 모델보다 약할 수 있으나, 개인 일정 입력 수준에서는 충분히
  실용적이라 판단.

## 4. 화면 / UX 흐름

- **메인 화면**: `UICalendarView` 월간 뷰. 일정이 있는 날짜에 도트 표시. 오늘로 이동 버튼.
- **날짜 탭 → 하단 시트**:
  - 상단: 해당 날짜의 일정 리스트(시간/제목). 길게 눌러 빠른 수정/삭제.
  - 하단: 챗 입력창. 자유 텍스트라 특정 날짜에 종속되지 않고 "월/수/금" 같은 여러
    날짜를 한 번에 지정하는 입력도 이 시트 하나에서 처리.
- **설정 화면**: 구글 계정 연결/해제, 알림 고정 시각 설정. AI API 키 입력 UI 없음
  (온디바이스라 불필요).
- 주간 아젠다 뷰 등 추가 화면은 MVP 이후로 미룸.

## 5. 데이터 흐름

**챗 기반 생성/수정/삭제/조회**
날짜 탭 → 하단 시트 열림 → 자연어 입력 → `ChatEngine`이 `LanguageModelSession`에 현재
날짜/최근 대화와 함께 전달 → 모델이 모호한 참조("수요일 미팅")를 `ListEventsTool`로
먼저 조회 → 확정되면 `CreateEventTool`/`UpdateEventTool`/`DeleteEventTool` 중 필요한
것을 연쇄 호출 → 삭제·수정처럼 되돌리기 어려운 액션은 실행 직전 확인 카드로 사용자
승인 요구 → 승인 시 `GoogleCalendarService`가 실제 API 호출 → 결과를 챗 말풍선으로 요약.

**일일 알림**
백그라운드 동기화 시점마다 최신 일정을 로컬 캐시에 저장 → 사용자가 설정한 고정 시각에
그 시점 최신 캐시 기준으로 알림 콘텐츠(오늘 일정 요약 + 내일 예고)를 생성/재예약.
iOS 특성상 정확한 시각 실행은 보장되지 않으며 "가장 최근 동기화 시점 기준" 값이 되는
트레이드오프가 있음 — MVP에서는 허용 가능한 수준으로 간주. 오늘/내일 모두 일정이 없는
날에도 "오늘 일정 없음" 형태로 알림을 보낸다(무음 처리하지 않음).

## 6. AI 명령 범위

챗 입력으로 지원하는 동작: 생성, 수정, 삭제, 조회(예: "이번주 일정 알려줘").
예시:
- 생성: "월/수/금(7/1,3,5) 오후1~3시 미팅"
- 수정: "수요일 미팅 4시로 미뤄줘"
- 삭제: "금요일 미팅 취소해줘"

반복 일정 규칙(RRULE) 생성은 지원하지 않음 — 명시적으로 나열된 날짜에 대해서만 개별
이벤트를 생성한다 (예시처럼 "월/수/금" 세 날짜를 지정하면 반복 규칙이 아닌 3개의 개별
이벤트로 생성).

## 7. 에러 처리

- OAuth 토큰 만료/거부 → 챗에 "구글 캘린더 연결이 끊어졌어요, 설정에서 다시
  로그인해주세요" 안내 + 설정으로 이동 버튼.
- Calendar API 실패(네트워크 없음/rate limit/권한 없음) → 챗에 실패 사유 요약 +
  재시도 버튼.
- 모델이 참조를 여러 개 찾음(동명의 일정 여러 개) → 후보를 나열하며 되묻기(멀티턴).
- 입력을 이해 못함 → "무슨 뜻인지 잘 모르겠어요, 다시 말씀해주시겠어요?" fallback.
- 확인 카드에서 사용자가 취소 → 아무 것도 실행하지 않고 "취소했어요"만 응답.

## 8. 보안

- Google OAuth 토큰은 Keychain에 저장, 앱 삭제 시 자동 폐기.
- PKCE 기반 네이티브 OAuth 플로우 사용 (클라이언트 시크릿 불필요).
- 온디바이스 AI이므로 일정 내용이 외부 서버로 전송되지 않음 — Google Calendar API
  호출만이 유일한 외부 통신.
- 개인용 단일 사용자 프로젝트로 별도 사용자 관리/권한 체계 불필요.

## 9. 테스트 전략

- `GoogleCalendarService`를 프로토콜로 추상화해 mock 처리 → Tool 실행 로직을 유닛
  테스트로 검증(대표 시나리오: 다중 날짜 생성, 모호한 참조 수정, 삭제 확인 플로우 등).
- 알림 문구 생성 로직은 순수 함수로 분리해 유닛 테스트.
- 온디바이스 모델 추론 자체는 비결정적이므로 "정확한 응답 문구"가 아니라 "올바른
  Tool이 올바른 파라미터로 호출되는지"를 기준으로 검증.
- 실기기(iPhone 15 Pro, iOS 26+)에서 수동 UI/E2E 테스트.

## 10. MVP 범위 제외 항목

- 다중 캘린더 선택 (구글 계정 내 여러 캘린더 중 선택) — 기본 캘린더 하나만 지원.
- 반복 일정(RRULE) 생성 — 명시적 날짜 나열만 지원.
- 위젯 / Apple Watch / 공유 확장.
- 캘린더 공유·초대 관리.
- 클라우드 폴백 AI — 완전 온디바이스로 확정, 폴백 없음.
